# 电缆隧道 BIM 软件立项方案：几何内核、渲染管线与场景落地

建议把下一阶段的部分开发资源倾斜到一个聚焦电缆隧道与电力 GIM 场景的轻量化 BIM 创作软件上。它的技术底座由四层构成：纯 Rust 的 B-Rep 几何内核承担建模与布尔运算，wgpu 承担跨平台渲染，IFC4X3 语义层承担数据互操作，而隐藏线消除（Hidden Line Removal，HLR）与曲面轮廓提取这类数值难度最高的几何计算，交由 OpenCASCADE（OCCT）以 WebAssembly 方式承担。这个组合的实质，是把"从零自研几何内核"的千万元级投入替换成"集成成熟开源内核 + 深耕单一行业场景"，从而把有限的工程人力集中到国产替代真正卡住的那一段——曲线路径放样、带洞口结构、以及可交付施工图的三维正向设计能力。

下表把方案在九个维度上的判断集中列出，便于快速对照。

| 维度 | 判断 |
| --- | --- |
| 想法 | 面向电缆隧道与电力 GIM 的轻量化 BIM 创作软件，纯 Rust 几何内核 + wgpu 渲染 |
| 模式 | 集成开源内核、自研场景层；软件授权、项目交付、平台集成三种变现方式并行 |
| 用途 | 三维正向设计建模、GIM 成果移交与评审、二维出图与施工交底 |
| 价值 | 以集成替代自研，压缩前期资金与时间门槛；对标国产替代与自主可控要求 |
| 竞品 | 国际为 Autodesk Revit、Bentley、ArchiCAD；国内为广联达、构力 BIMBase、恒华 |
| 市场前景 | 中国 BIM 软件与服务为百亿元级市场，政策持续要求国产 BIM 软件生态与正向设计 |
| 开发成本 | 分三阶段推进，首期集中在内核集成与出图链路，避开通用 CAD 的正面竞争 |
| 亮点 | 纯 Rust 工具链、双内核分工、WASM 降级路径、电缆隧道场景纵深 |
| 数学与技术背书 | 精确 B-Rep/NURBS 表示、HLR 投影算法、浮点容差体系、GPU 并行渲染 |

九项判断中真正决定成败的是两条：内核路线决定成本量级，场景纵深决定能否在既有厂商的优势区间之外立足。其余各节围绕这两条展开。

## 一、项目构想与定位

国家电网把 GIM 定义为"电网的 BIM 数据模型标准"，并在此之上建立了覆盖建模、协同、评审与移交的标准体系【19】。围绕三维设计成果的行业与团体标准已经成型，公开标准信息平台上可以查到电力行业三维设计成果移交、输变电工程三维协同设计以及电力电缆隧道设计规程等一系列编号标准【34】【33】。这意味着一件事：在电网系统内做三维设计工具，交付物的数据结构、精度分级与移交格式都是被规定好的，软件的自由度在"怎么建模、怎么出图"，而不在"用什么数据模型"。

这正好是一个收敛的切入点。通用 BIM 平台需要在建筑、结构、机电、市政之间做平衡，很难为单一场合下的混凝土结构断面、电缆支架间距、隧道曲线线性做深度优化；而电缆隧道恰恰是一个几何特征高度规整、行业标准高度明确、且必须出二维施工图的小切口。方案据此把产品边界定为三条：主力几何存储采用精确 B-Rep，三角网格只用于查看、校验与流转；二维出图做成自建轻量模块，而不是再引入一套完整 CAD；电缆隧道的曲线路径放样与带洞口结构做到可用、可出图、可移交，不追求复杂自由曲面的布尔运算能力。

需要说明边界之外的判断。纯网格主存储做正向设计、以及仅为出图而再引入完整 OCCT 建模栈，这两条路线都不采纳：前者无法满足 GIM 对 DEV 层 B-Rep 解析的要求，后者会把项目重新拖回"集成一个重型 C++ 内核"的老路径，失去轻量化的全部意义。

## 二、产品形态与交付模式

产品形态按三种终端组织。桌面端是主战场，承担大体量装配与出图；浏览器端以 WebAssembly 承载几何内核，使模型查看、轻量编辑与协同评审无需安装；服务端承担模型转换、批量出图与项目级数据管理。三者共用同一套 Rust 几何与渲染代码，这是选择 Rust 作为主语言的直接收益。

交付模式上，方案不押注单一变现路径。软件授权面向设计院与施工单位，按席位或按年订阅；项目交付面向具体工程的 GIM 建模与成果移交，按项目结算；平台集成面向已有电力信息化厂商，把几何与出图能力作为组件输出。三条路径的风险特征不同：授权依赖产品成熟度，项目交付依赖行业关系，组件输出依赖技术通用性；其中项目交付最容易在早期产生现金流，用于反哺产品化。

开源合规是模式设计中不能回避的一环。OCCT 采用 LGPL 系许可证，其义务边界在 GNU 官方问答与实务解读中表述明确：静态链接 LGPL 库时，必须提供应用自身的可重链接目标代码，以便使用者替换库版本；若自行随应用分发该库的可执行文件，仍须随附该库源码；若库已存在于用户机器上而仅动态调用，则无需随附源码；修改库本身则须以 LGPL 公开修改内容与日期，并在最终用户协议中去掉反逆向条款或增设例外【14】【15】【16】【17】。据此，方案倾向于让 OCCT 以独立的 WASM 模块形式存在、通过动态加载调用，从而把合规负担控制在可接受范围，而不是走原生静态链接 OCCT 的路线。这条技术选择同时是合规选择。

## 三、目标用途与作业流程

第一类用途是三维正向设计。设计人员在软件内建立电缆隧道本体、电缆支架、通风与排水附属结构以及电缆敷设路径，几何数据以 B-Rep 保存，精度分级按标准要求的模型细度组织。第二类用途是 GIM 成果移交与评审，软件按行业标准输出结构化模型与图纸，进入评审与移交流程。第三类用途是二维出图与施工交底，由三维模型生成平、立、剖面图纸与节点详图，直接服务于现场施工。

三类用途串成同一条作业链路：建模 → 校验 → 出图 → 移交。这条链路上真正稀缺的环节是出图。Rust 原生 B-Rep 内核普遍缺少 HLR 与轮廓提取能力，而 HLR 是把三维体正确投影成二维工程图的必要步骤；缺少它，软件只能做三维预览，无法产出可交付的施工图。方案对该环节给出的解法，是由 Rust 端完成几何取证，把消隐计算下推给 OCCT 的精确投影算法，再回到 Rust 端用 lyon 或 wgpu 绘制粗线与管状线，或导出 DXF 的 LWPOLYLINE 与 SVG 的 stroke-width 表达线宽。

## 四、价值主张与收益结构

对使用方而言，价值集中在三点：图形与几何能力完全落在自主可控的代码路径上，规避国际软件的授权与断供风险；面向电缆隧道的专业功能替代通用平台的低效操作，缩短建模与出图工时；按行业标准组织的成果输出，减少设计与施工之间的反复修改。这三点对应的都是可度量的作业成本，而不是概念上的先进性。

对我方而言，价值在于用一段可控的工程投入换取一个有壁垒的技术位。壁垒不来自通用几何能力——那需要十年以上的持续投入才能与国际内核比肩——而来自"电缆隧道 + 电力 GIM + 可出图"这一组合场景的深度适配。通用厂商不会为单一断面形式与单一专业流程做深度优化，专业厂商则普遍缺少底层几何与渲染的自主能力，两者的空档就是本项目的位置。

## 五、竞争格局与在位厂商

国际市场上，Autodesk Revit、Bentley 系列与 ArchiCAD 构成通用 BIM 平台的第一梯队，功能完整但体量沉重，中国区报价未在公开渠道检索到可比数据。国内市场上，广联达、鲁班、构力科技 BIMBase 等构成主力，其中广联达已有面向电力隧道的三维设计产品【20】，构力科技公开表示其 BIMBase 核心代码 100% 自研【21】；在电力三维设计这一细分方向，恒华科技的三维线路设计系列软件长期服务国内输变电工程建设领域，公司自述"取得相对领先的市场地位"，并披露了 DH3D、BIMEngine、GIMEngine 等自研底层技术平台【19】。恒华科技 2025 年年度报告显示，公司营业收入 89,515.23 万元，同比下降 6.42%，归属于上市公司股东的净利润为 -22,846.20 万元，扣除非经常性损益后为 -23,253.40 万元，加权平均净资产收益率 -13.11%，并将亏损归因于行业竞争加剧压缩利润与订单、新能源市场化改革降低投资热情、以及应收与合同资产计提减值【18】。

这份财务数据有两个方向的读法。它说明在位者正承受激烈竞争与盈利压力，新进入者面对的是价格战而非宽松市场；但它同时说明，在位者的护城河并没有转化为稳定的盈利结构，行业格局仍在变动之中。对方案而言，更稳妥的定位是承认这一细分市场的竞争强度，并把差异化放在"在位者尚未覆盖的几何与出图自主能力"上，而不是假设市场存在空缺。

技术侧的同类探索提供了两面证据。Fornjot 项目在运行约六年后由创建者关闭，说明用 Rust 从零构建通用 CAD 内核的难度与周期远超预期【11】。Truck 作为 Rust 原生 B-Rep 内核，具备 NURBS、布尔、放样、偏移与 STEP 读写能力，采用 MIT/Apache-2.0 许可【1】；其分支形态 monstertruck 曾以硬分叉方式回退一次布尔运算重写，作者自述该项目"更像一处有前景的研究矿脉，而不是可安全用于生产的几何内核"，并面临单人维护的风险【2】【3】。brepkit 声称覆盖完整 B-Rep 并在较新版本中把许可证从 MIT/Apache 转为 AGPL-3.0-only，重合面、同轴、极薄与高面数场景下的布尔运算会回退到网格，圆环体布尔存在缺口【4】。Web 侧则出现了以 OCCT 编译为 WASI-Wasm 的 occt-wasm【5】、以及把 OCCT 7.9.3 的 HLR 结果输出为 SVG 的 occt.ts 等方案【6】，后者采用 LGPL-2.1。类似定位的轻量化编辑器还有 Astral3D、Pascal Editor 与 CADmium【35】【36】【37】【38】。同类 Web 实现中，nopp.dev/rk 默认采用 OCCT 内核，其 truck 特性尚不能完成布尔减运算，这也从侧面印证了纯 Rust 内核在通用建模上的能力边界【10】。

把这些放在一起可以看清本项目的真实坐标：它不是在一个无人区里开发，而是在一个已有多个失败与半成品先例的赛道上，选择一条避开通用内核难点的窄路。方案不主张"市面上缺少同类成熟软件"，而是主张"通用 BIM 平台、专业电力设计软件与轻量化开源编辑器三者之间存在组合能力空白"——即同时满足纯 Rust 工具链、精确 B-Rep 主存储、可交付二维出图和电缆隧道专业适配的软件，目前尚无成熟产品。

## 六、市场前景与政策窗口

市场规模的公开口径分歧较大，需要在引用时保留范围。中国 BIM 解决方案市场有 309.33 亿元的统计口径，其中软件与服务约 216.8 亿元【29】；也有以 94 亿元为起点、预测增长到 228 亿美元的口径，与前者在量级与币种上均无法直接比较【30】。全球范围，BIM 软件市场有 53.08 亿美元的口径【31】，中国市场的独立统计则给出另一组区间【32】。这些差异来自统计边界——是否包含咨询、培训与运维，是否包含硬件与服务——因此在方案中不宜给出单一确定性数字，而应表述为"百亿元级并保持两位数增长"。

政策面的信号方向一致。住房和城乡建设部发布《智能建造技术导则（试行）》，多部门文件提出打通软件间数据壁垒、构建国产 BIM 软件应用生态；行业媒体对国产 BIM 底层平台的攻关进展也有持续报道【21】。与之配套的标准体系持续推进，GB/T 45393 系列国家标准在 2025 年发布并实施【33】。这构成了一个明确的采购环境：政府投资项目与电网系统项目在设计交付环节被要求使用三维设计与国产软件，需求侧由合规驱动而非纯效率驱动。

驱动与阻力同时存在。合规要求带来的是确定性的入门机会，但客户的更换成本高、学习曲线长，且设计院对既有工具的路径依赖很强。方案据此把市场策略定为"先场景后通用"：先在电缆隧道这一单一场景内做到可用并交付若干实际工程，用可验证的出图质量建立信任，再横向复制到其他电力构筑物类型，而不是一开始就对标通用 BIM 平台的功能清单。

## 七、开发成本与投入测算

成本论证的参照系来自国产几何内核的公开表述。九韶智能的内核经过多年持续迭代并发布多个大版本，对外宣称已跻身全球主要商用几何内核之列，其背后是成建制的稀缺团队【22】【23】。华天软件的皇冠 CAD 经历了三十余年积累与上亿行量级的代码规模。业内有以"不低于 2000 万元红线、十人以上团队、三年达到初步可用"来描述自研内核投入门槛的估算，也有"二十人以上、十年以上持续投入"的说法【24】【25】【26】【27】。国产 CAD 厂商对自身短板的公开总结同样指向这一方向：三维核心引擎的超大装配性能、布尔与圆角抽壳的成功率与稳定性、以及中间格式的鲁棒性，是需要长期投入才能补齐的部分【28】。

下表把几条参照路径与本方案的成本结构并列，便于比较前期投入的分布。

| 路径 | 前期投入特征 | 主要风险 |
| --- | --- | --- |
| 从零自研通用几何内核 | 千万元级资金，十人以上团队，三年以上周期 | 周期与结果不确定，容易重演通用 CAD 内核的失败先例 |
| 原生静态链接 OCCT | 需 C++ 工具链，性能最优 | LGPL 静态链接合规负担高，交付物受许可约束 |
| OCCT 编译为 WASM 动态加载 | 无需 C++ 工具链，性能有折损 | 性能约为原生的两倍开销，需评估大装配场景 |
| 本方案：Rust 内核 + OCCT 仅承担 HLR | 集成与场景适配为主，人力集中在业务层 | 依赖上游内核成熟度，需自建关键模块 |

这张表的核心差异在最后一列与前两列的落差：不做通用内核，等于把资金风险从"能否造出来"转换为"能否用好现成构件"。方案据此申请的资源，并不是一个通用内核的研发预算，而是一个小型团队围绕集成、出图与场景适配的工程预算，量级上低一个数量级。

## 八、重点亮点与差异化路径

差异化集中在四个可以验证的技术点上。第一是双内核分工：Rust 内核承担主力建模与几何存储，OCCT 仅承担 HLR 消隐与曲面轮廓提取，用最小面积的重型依赖换取工程出图能力。第二是 WASM 降级路径：occt-wasm 以预编译的 WASI-Wasm 形式提供，可直接由 wasmtime 加载，无需 C++ 与 CMake 工具链，4.7MB 压缩体积、解压后约 21MB，代价是约两倍于原生的开销【5】。第三是纯 Rust 二维出图链路：以 kurbo 做曲线、rstar 做空间索引、lyon 做镶嵌、ttf-parser 与 rustybuzz 做文字、dxf 库做 DXF 读写，DXF 侧已有成熟 Rust 实现可供选择【12】【13】。第四是场景纵深：曲线路径放样与带洞口结构是电缆隧道的几何特征，通用平台在这两类操作上的效率损失是可直接观测的。

需要同时说明技术上的明确缺口。Rust 原生 B-Rep 生态在 HLR 与轮廓提取上确实存在空白，这不是可以回避的问题；自研该能力需要人月级投入，且 NURBS 相切求解的数值稳定性难以保证；屏幕空间后处理只能用于预览、不能用于出图；VTK 与 ParaView 一类通用可视化库不适用于 BIM 的图纸语义。方案选择把这部分交给 OCCT，是在承认自身短板的前提下做出的取舍，而不是在技术上宣称已经解决。

## 九、数学基础与技术背书

几何层的数学基础是精确 B-Rep 与 NURBS。B-Rep 用参数曲面与拓扑面、边、顶点的关联描述实体，能够精确表达解析曲面与自由曲面，布尔运算与倒角、抽壳等操作都定义在这一表示上；NURBS 用带权控制点与节点向量统一表达直线、圆弧与自由曲线，是 STEP 等交换格式的基础表示。这套表示在本项目中承担几何存储与交换的双重职责，也是 GIM 的 DEV 层要求解析 B-Rep 的原因。

出图链路的数学核心是 HLR。OCCT 的消隐由视图计算模式驱动，其中提供基于多面体的近似算法与精确算法两种选择，精确路径以 HLRAlgo_Projector 与 HLRBRep 算法族实现轮廓与可见性判定【7】【8】；商用内核如 Spatial 的 CGM 也把 HLR 作为独立能力提供【9】。本项目调用的是精确路径，以保证图纸轮廓的几何正确性。数值上，几何运算的容差体系需要统一设计，取 1e-6 至 1e-8 量级的 eps 用于点重合、面贴合与自交判定，容差过松会误判相交，过紧则让布尔运算在退化情形下失败。

渲染层基于 W3C 的 WebGPU 规范，着色器语言为 WGSL，可在同一套代码下覆盖桌面与浏览器【39】【40】。工程上将几何计算与渲染解耦：几何在内核侧完成，渲染只消费网格与轮廓数据，这样即使内核或消隐模块更换实现，渲染层无需改动。性能策略是把大装配的几何分解为可并行任务，在桌面端利用多线程、在浏览器端利用 Worker，把 WASM 模块的加载与计算放在渲染主线程之外。

## 十、风险边界与分阶段推进

技术风险中最需要正视的是上游内核成熟度。monstertruck 存在单人维护问题，brepkit 在部分布尔场景回退到网格且许可证转为 AGPL-3.0-only，这两个约束都要求项目在选型时不把全部关键路径绑定在单一上游，并在许可证层面预留替换方案【2】【3】【4】。市场风险来自在位者的价格与关系优势，恒华科技的亏损说明这是一个竞争充分的市场，需要接受早期必须依靠项目交付而非产品授权获得收入【18】。合规风险集中在 OCCT 的 LGPL 义务，缓解手段是采用 WASM 动态加载并建立许可证合规检查点【14】【15】【16】【17】。人员风险是团队规模小、同时覆盖几何、渲染与行业业务，任何一环缺人都会拖慢整体。

推进按三个阶段组织。

| 阶段 | 目标 | 验收标准 |
| --- | --- | --- |
| 第一阶段 | 打通内核集成与出图链路 | 能对电缆隧道断面完成建模并通过 HLR 生成二维图纸 |
| 第二阶段 | 完成场景功能与标准对齐 | 曲线路径放样、带洞口结构可用，成果符合行业标准要求 |
| 第三阶段 | 完成首个实际工程交付 | 在真实项目中完成建模、出图与移交全链路 |

三个阶段的设置意图是把技术不确定性与商业不确定性分开验证：第一阶段只验证"能不能出图"，第二阶段验证"能不能符合标准"，第三阶段才验证"客户愿不愿意用"。任一阶段的验收标准未达成，都应在进入下一阶段前重新评估路线，而不是靠追加投入掩盖问题。
