## 一、想法：这个项目到底在做什么

### 1.1 缘起

国家电网把 GIM 定义为"电网的 BIM 数据模型标准"，并在此之上建立了覆盖建模、协同、评审与移交的标准体系【19】。围绕三维设计成果的行业与团体标准已经成型，公开标准信息平台上可以查到电力行业三维设计成果移交、输变电工程三维协同设计以及电力电缆隧道设计规程等一系列编号标准【34】【33】。

这意味着一件事：**在电网系统内做三维设计工具，交付物的数据结构、精度分级与移交格式都是被规定好的，软件的自由度在"怎么建模、怎么出图"，而不在"用什么数据模型"。**

### 1.2 核心思想（一句话）

**把"从零自研几何内核"的千万元级投入，替换成"集成成熟开源内核 + 深耕单一行业场景"，从而把有限的工程人力集中到国产替代真正卡住的那一段——曲线路径放样、带洞口结构，以及可交付施工图的三维正向设计能力。**

产品边界据此收敛为三条：

1. **主力几何存储采用精确 B-Rep**，三角网格只用于查看、校验与流转；
2. **二维出图做成自建轻量模块**，而不是再引入一套完整 CAD；
3. **电缆隧道的曲线路径放样与带洞口结构做到可用、可出图、可移交**，不追求复杂自由曲面的布尔运算能力。

### 1.3 技术底座的构成（四层）

| 层 | 承担者 | 职责 |
|---|---|---|
| 几何内核 | 纯 Rust B-Rep | 建模与布尔运算 |
| 渲染管线 | wgpu | 跨平台渲染（桌面 + 浏览器） |
| 语义层 | IFC4X3 | 数据互操作 |
| 消隐/轮廓 | OpenCASCADE（OCCT，以 WebAssembly 方式） | 隐藏线消除（HLR）与曲面轮廓提取——数值难度最高的几何计算 |

> **必须明确边界之外的判断**：纯网格主存储做正向设计、以及仅为出图而再引入完整 OCCT 建模栈，这两条路线都**不采纳**。前者无法满足 GIM 对 DEV 层 B-Rep 解析的要求；后者会把项目重新拖回"集成一个重型 C++ 内核"的老路径，失去轻量化的全部意义。

## 二、模式：产品与技术模式

### 2.1 产品形态（三种终端）

| 终端 | 定位 | 承载能力 |
|---|---|---|
| **桌面端** | 主战场 | 大体量装配与出图 |
| **浏览器端** | 轻量协同 | 以 WebAssembly 承载几何内核，模型查看、轻量编辑与协同评审无需安装 |
| **服务端** | 后台支撑 | 模型转换、批量出图与项目级数据管理 |

三者**共用同一套 Rust 几何与渲染代码**，这是选择 Rust 作为主语言的直接收益。

### 2.2 交付模式（不押注单一变现路径）

| 模式 | 面向客户 | 结算方式 | 风险特征 |
|---|---|---|---|
| **软件授权** | 设计院与施工单位 | 按席位 / 按年订阅 | 依赖产品成熟度 |
| **项目交付** | 具体工程的 GIM 建模与成果移交 | 按项目结算 | 依赖行业关系，**最容易在早期产生现金流，用于反哺产品** |
| **平台集成** | 已有电力信息化厂商 | 把几何与出图能力作为组件输出 | 依赖技术通用性 |

### 2.3 开源合规是模式设计中不能回避的一环

OCCT 采用 LGPL 系许可证，其义务边界在 GNU 官方问答与实务解读中表述明确：

- 静态链接 LGPL 库时，**必须提供应用自身的可重链接目标代码**，以便使用者替换库版本；
- 若自行随应用分发该库的可执行文件，仍须**随附该库源码**；
- 若库已存在于用户机器上而仅动态调用，则**无需随附源码**；
- 修改库本身则须以 LGPL 公开修改内容与日期，并在最终用户协议中去掉反逆向条款或增设例外【14】【15】【16】【17】。

> **据此，方案倾向于让 OCCT 以独立的 WASM 模块形式存在、通过动态加载调用**，从而把合规负担控制在可接受范围，而不是走原生静态链接 OCCT 的路线。**这条技术选择同时是合规选择。**

## 三、用途：核心应用场景

### 3.1 三类用途（按优先级）

1. **三维正向设计**：设计人员在软件内建立电缆隧道本体、电缆支架、通风与排水附属结构以及电缆敷设路径，几何数据以 B-Rep 保存，精度分级按标准要求的模型细度组织。
2. **GIM 成果移交与评审**：软件按行业标准输出结构化模型与图纸，进入评审与移交流程。
3. **二维出图与施工交底**：由三维模型生成平、立、剖面图纸与节点详图，直接服务于现场施工。

### 3.2 作业链路

三类用途串成同一条作业链路：**建模 → 校验 → 出图 → 移交**。

### 3.3 真正稀缺的环节：出图

Rust 原生 B-Rep 内核普遍缺少 HLR 与轮廓提取能力，而 **HLR 是把三维体正确投影成二维工程图的必要步骤**；缺少它，软件只能做三维预览，无法产出可交付的施工图。

方案对该环节给出的解法：

```
由 Rust 端完成几何取证
  → 把消隐计算下推给 OCCT 的精确投影算法
  → 回到 Rust 端用 lyon 或 wgpu 绘制粗线与管状线
  → 或导出 DXF 的 LWPOLYLINE 与 SVG 的 stroke-width 表达线宽
```

## 四、价值：对客户、对公司

### 4.1 客户价值

| 价值点 | 说明 |
|---|---|
| **自主可控** | 图形与几何能力完全落在自主可控的代码路径上，规避国际软件的授权与断供风险 |
| **专业替代通用** | 面向电缆隧道的专业功能替代通用平台的低效操作，缩短建模与出图工时 |
| **标准对齐** | 按行业标准组织的成果输出，减少设计与施工之间的反复修改 |

> 这三点对应的都是**可度量的作业成本**，而不是概念上的先进性。

### 4.2 公司价值（战略意义）

1. **以集成替代自研，压缩前期资金与时间门槛**：不做通用内核，等于把资金风险从"能否造出来"转换为"能否用好现成构件"。
2. **用一段可控的工程投入换取一个有壁垒的技术位**：壁垒不来自通用几何能力——那需要十年以上的持续投入才能与国际内核比肩——而来自"**电缆隧道 + 电力 GIM + 可出图**"这一组合场景的深度适配。
3. **卡位空档区**：通用厂商不会为单一断面形式与单一专业流程做深度优化，专业厂商则普遍缺少底层几何与渲染的自主能力，**两者的空档就是本项目的位置**。

## 五、竞品：市场上有什么，我们差在哪、强在哪

### 5.1 竞品全景

| 类别 | 代表产品 | 能力 | 短板（我们的机会） |
|---|---|---|---|
| **国际通用 BIM 平台** | Autodesk Revit、Bentley 系列、ArchiCAD | 功能完整，第一梯队 | 体量沉重，需在建筑/结构/机电/市政间平衡，**难为单一场景深度优化**；中国区报价未在公开渠道检索到可比数据 |
| **国内主力 BIM 平台** | 广联达、鲁班、构力科技 BIMBase | 本土主力 | 广联达已有面向电力隧道的三维设计产品【20】；构力科技公开表示其 BIMBase 核心代码 100% 自研【21】 |
| **电力三维设计专业厂商** | 恒华科技（DH3D、BIMEngine、GIMEngine 等自研底层平台） | 长期服务国内输变电工程建设领域，公司自述"取得相对领先的市场地位"【19】 | 2025 年年度报告显示营收 89,515.23 万元（同比 −6.42%），归母净利润 −22,846.20 万元，加权平均净资产收益率 −13.11%【18】 |
| **Rust 原生 B-Rep 内核** | Truck、monstertruck、brepkit | 具备 NURBS、布尔、放样、偏移与 STEP 读写等能力【1】 | monstertruck 自述"更像一处有前景的研究矿脉，而不是可安全用于生产的几何内核"，面临单人维护风险【2】【3】；brepkit 在重合面、同轴、极薄与高面数场景下布尔运算会回退到网格，圆环体布尔存在缺口，许可证转为 AGPL-3.0-only【4】 |
| **Web 侧 OCCT 方案** | occt-wasm（OCCT 编译为 WASI-Wasm）、occt.ts（OCCT 7.9.3 的 HLR 结果输出为 SVG） | 提供 WASM/WASI 形态的 OCCT 与 HLR→SVG 能力【5】【6】 | occt.ts 采用 LGPL-2.1；occt-wasm 性能约为原生两倍开销 |
| **轻量化编辑器** | Astral3D、Pascal Editor、CADmium | Web 三维与 BIM 轻量化编辑【35】【36】【37】【38】 | nopp.dev/rk 默认采用 OCCT 内核，其 truck 特性尚不能完成布尔减运算【10】，从侧面印证纯 Rust 内核在通用建模上的能力边界 |

### 5.2 两份必须正视的反例证据

**技术侧的失败与半成品先例**：Fornjot 项目在运行约六年后由创建者关闭，说明**用 Rust 从零构建通用 CAD 内核的难度与周期远超预期**【11】；Truck 分支 monstertruck 曾以硬分叉方式回退一次布尔运算重写【2】【3】；brepkit 的布尔运算在部分场景回退到网格【4】。

**在位者的财务证据**：恒华科技 2025 年年报显示亏损，并将原因归因于行业竞争加剧压缩利润与订单、新能源市场化改革降低投资热情、以及应收与合同资产计提减值【18】。这份数据有两个方向的读法：

> 它说明在位者正承受激烈竞争与盈利压力，**新进入者面对的是价格战而非宽松市场**；但它同时说明，在位者的护城河并没有转化为稳定的盈利结构，**行业格局仍在变动之中**。

### 5.3 关键结论（可防守的表述）

把这些放在一起可以看清本项目的真实坐标：**它不是在一个无人区里开发，而是在一个已有多个失败与半成品先例的赛道上，选择一条避开通用内核难点的窄路。**

方案不主张"市面上缺少同类成熟软件"，而是主张：

> **通用 BIM 平台、专业电力设计软件与轻量化开源编辑器三者之间存在"组合能力空白"——即同时满足纯 Rust 工具链、精确 B-Rep 主存储、可交付二维出图和电缆隧道专业适配的软件，目前尚无成熟产品。**

### 6.3 驱动与阻力并存

| 方向 | 内容 |
|---|---|
| **驱动** | 合规要求带来确定性的入门机会 |

| **对策** | 市场策略定为**"先场景后通用"**：先在电缆隧道这一单一场景内做到可用并交付若干实际工程，用可验证的出图质量建立信任，再横向复制到其他电力构筑物类型，而不是一开始就对标通用 BIM 平台的功能清单 |

## 七、开发成本：要投多少人、多少钱

### 7.1 成本论证的参照系

参照系来自国产几何内核的公开表述：

- 九韶智能的内核经过多年持续迭代并发布多个大版本，对外宣称已跻身全球主要商用几何内核之列，其背后是成建制的稀缺团队【22】【23】；
- 华天软件的皇冠 CAD 经历了三十余年积累与上亿行量级的代码规模；
- 业内有以"不低于 2000 万元红线、十人以上团队、三年达到初步可用"来描述自研内核投入门槛的估算，也有"二十人以上、十年以上持续投入"的说法【24】【25】【26】【27】；
- 国产 CAD 厂商对自身短板的公开总结同样指向这一方向：三维核心引擎的超大装配性能、布尔与圆角抽壳的成功率与稳定性、以及中间格式的鲁棒性，都是需要长期投入才能补齐的部分【28】。

### 7.2 参照路径与本方案的成本结构对比

| 路径 | 前期投入特征 | 主要风险 |
|---|---|---|
| 从零自研通用几何内核 | 千万元级资金，十人以上团队，三年以上周期 | 周期与结果不确定，容易重演通用 CAD 内核的失败先例 |
| 原生静态链接 OCCT | 需 C++ 工具链，性能最优 | LGPL 静态链接合规负担高，交付物受许可约束 |
| OCCT 编译为 WASM 动态加载 | 无需 C++ 工具链，性能有折损 | 性能约为原生的两倍开销，需评估大装配场景 |
| **本方案：Rust 内核 + OCCT 仅承担 HLR** | **集成与场景适配为主，人力集中在业务层** | 依赖上游内核成熟度，需自建关键模块 |

> 这张表的核心差异在最后一列与前两列的落差：**不做通用内核，等于把资金风险从"能否造出来"转换为"能否用好现成构件"。**
> 方案据此申请的资源，并不是一个通用内核的研发预算，而是一个**小型团队围绕集成、出图与场景适配的工程预算，量级上低一个数量级**。

## 八、重点亮点：差异化集中在四个可验证的技术点

| # | 亮点 | 内容 |
|---|---|---|
| 1 | **双内核分工** | Rust 内核承担主力建模与几何存储，OCCT 仅承担 HLR 消隐与曲面轮廓提取，用最小面积的重型依赖换取工程出图能力 |
| 2 | **WASM 降级路径** | occt-wasm 以预编译的 WASI-Wasm 形式提供，可由 wasmtime 直接加载，无需 C++ 与 CMake 工具链；4.7MB 压缩体积、解压后约 21MB，代价是约两倍于原生的开销【5】 |
| 3 | **纯 Rust 二维出图链路** | kurbo 做曲线、rstar 做空间索引、lyon 做镶嵌、ttf-parser 与 rustybuzz 做文字、dxf 库做 DXF 读写；DXF 侧已有成熟 Rust 实现可供选择【12】【13】 |
| 4 | **场景纵深** | 曲线路径放样与带洞口结构是电缆隧道的几何特征，通用平台在这两类操作上的效率损失是**可直接观测的** |

> **边界提醒（对内外统一口径）**：同时必须说明技术上的**明确缺口**——Rust 原生 B-Rep 生态在 HLR 与轮廓提取上确实存在空白，这不是可以回避的问题；自研该能力需要人月级投入，且 NURBS 相切求解的数值稳定性难以保证；屏幕空间后处理只能用于预览、不能用于出图；VTK 与 ParaView 一类通用可视化库不适用于 BIM 的图纸语义。**方案选择把这部分交给 OCCT，是在承认自身短板的前提下做出的取舍，而不是在技术上宣称已经解决。**

## 九、数学与技术背书

### 9.1 几何层：精确 B-Rep 与 NURBS

- **B-Rep** 用参数曲面与拓扑面、边、顶点的关联描述实体，能够精确表达解析曲面与自由曲面，**布尔运算与倒角、抽壳等操作都定义在这一表示上**；
- **NURBS** 用带权控制点与节点向量统一表达直线、圆弧与自由曲线，是 STEP 等交换格式的基础表示。

> 这套表示在本项目中承担**几何存储与交换的双重职责**，也是 GIM 的 DEV 层要求解析 B-Rep 的原因。

### 9.2 出图链路：HLR（消隐）

OCCT 的消隐由视图计算模式驱动，其中提供基于多面体的近似算法与精确算法两种选择，精确路径以 `HLRAlgo_Projector` 与 `HLRBRep` 算法族实现轮廓与可见性判定【7】【8】；商用内核如 Spatial 的 CGM 也把 HLR 作为独立能力提供【9】。

> **本项目调用的是精确路径**，以保证图纸轮廓的几何正确性。

**数值容差体系**：几何运算的容差需要统一设计，取 **1e-6 至 1e-8 量级**的 eps 用于点重合、面贴合与自交判定；容差过松会误判相交，过紧则让布尔运算在退化情形下失败。

### 9.3 渲染层：WebGPU / WGSL

- 基于 W3C 的 WebGPU 规范，着色器语言为 WGSL，可在同一套代码下覆盖桌面与浏览器【39】【40】；
- **工程上将几何计算与渲染解耦**：几何在内核侧完成，渲染只消费网格与轮廓数据；这样即使内核或消隐模块更换实现，渲染层无需改动；
- **性能策略**：把大装配的几何分解为可并行任务，在桌面端利用多线程、在浏览器端利用 Worker，把 WASM 模块的加载与计算放在渲染主线程之外。

## 十、落地路线图与风险边界

### 10.1 分阶段推进

| 阶段 | 目标 | 验收标准 |
|---|---|---|
| **第一阶段** | 打通内核集成与出图链路 | 能对电缆隧道断面完成建模并通过 HLR 生成二维图纸 |
| **第二阶段** | 完成场景功能与标准对齐 | 曲线路径放样、带洞口结构可用，成果符合行业标准要求 |
| **第三阶段** | 完成首个实际工程交付 | 在真实项目中完成建模、出图与移交全链路 |

> 三个阶段的设置意图是**把技术不确定性与商业不确定性分开验证**：第一阶段只验证"能不能出图"，第二阶段验证"能不能符合标准"，第三阶段才验证"客户愿不愿意用"。**任一阶段的验收标准未达成，都应在进入下一阶段前重新评估路线，而不是靠追加投入掩盖问题。**

### 10.2 风险清单（按严重度排序）

| 优先级 | 风险 | 说明 | 应对 |
|---|---|---|---|
| **P0** | **上游内核成熟度** | monstertruck 存在单人维护问题，brepkit 部分布尔场景回退网格且许可证转为 AGPL-3.0-only【2】【3】【4】 | 选型时不把全部关键路径绑定在单一上游，并在许可证层面预留替换方案 |
| **P0** | **合规风险** | 集中于 OCCT 的 LGPL 义务【14】【15】【16】【17】 | 采用 WASM 动态加载，并建立许可证合规检查点 |
| P1 | 市场风险 | 在位者的价格与关系优势；恒华科技亏损说明这是竞争充分的市场【18】 | 接受早期必须依靠项目交付而非产品授权获得收入 |
| P1 | 技术缺口 | HLR 与轮廓提取需依赖 OCCT，自研数值稳定性难保证 | 明确不承诺"已解决"，以集成方案替代自研 |
| P2 | 人员风险 | 团队规模小，同时覆盖几何、渲染与行业业务 | 任何一环缺人都会拖慢整体，需聚焦场景避免摊薄 |

## 十一、结论与请示事项

### 11.1 结论

1. **方向成立**：面向电缆隧道与电力 GIM 的轻量化 BIM 创作软件，**以集成成熟开源内核替代从零自研**，是一个真实存在的"组合能力空白"。但须准确表述：**不是"没有成熟软件"，而是"没有产品同时打通『纯 Rust 工具链 + 精确 B-Rep 主存储 + 可交付二维出图 + 电缆隧道专业适配』这个组合"。**
2. **技术可行**：两核分工（Rust 内核 + OCCT 承担 HLR）路线清晰；WASM 动态加载既解决轻量化也解决 LGPL 合规；B-Rep/NURBS、HLR 精确算法、WebGPU 渲染均有成熟工程先例背书。
3. **成本可控**：**不做通用内核研发，做集成 + 出图 + 场景适配的工程预算**，投入量级比"自研通用几何内核"低一个数量级。
4. **价值明确**：对客户是"自主可控 + 专业替代 + 标准对齐"；对公司是"以集成替代自研 + 可控投入换取技术位 + 卡位通用与专业厂商之间的空档"。
5. **风险清晰**：P0 风险为**上游内核成熟度**与**OCCT 的 LGPL 合规**；另有市场（在位者价格战）与人员（小团队多面覆盖）P1/P2 风险，均已在第 10.2 节列明应对。

### 11.2 请示事项（资源倾斜建议）

| 事项 | 建议 |
|---|---|
| **立项** | 批准立项，先做第一阶段（内核集成与出图链路）的可行性原型 |
| **人力** | 组建小型团队，围绕**集成、出图与场景适配**配置，而非通用内核研发编制 |
| **口径** | 对外统一为"**面向电缆隧道的轻量化 BIM 创作软件**"，**不宣称"从零自研几何内核"**，核心资产是双内核分工 + 纯 Rust 出图链路 + 场景纵深 |
| **决策点** | 第一阶段验收（能对电缆隧道断面完成建模并通过 HLR 生成二维图纸）通过后，再批准进入第二阶段 |
| **合规** | 建立 OCCT 的 LGPL 合规检查点，坚持 WASM 动态加载路线 |

## 附录：一句话电梯陈述

> **我们做的是电力场景的"轻量化 BIM 创作软件"：以纯 Rust 的 B-Rep 内核 + wgpu 渲染为底座，只把最难的消隐与轮廓提取交给 OpenCASCADE（以 WASM 方式集成），让设计人员在软件内完成电缆隧道本体的三维正向设计，并直接产出可交付的二维施工图。它解决的是"通用 BIM 平台不为单一场景深度优化、专业厂商又缺少底层几何自主能力"这个长期断裂。我们不从零造通用内核，而是把有限的工程人力集中到国产替代真正卡住的那一段——曲线路径放样、带洞口结构与可出图的三维正向设计能力。这，就是我们的位置。**
